# AGENTS.md — правила для агентов в этом репозитории

## Документация

Вся документация по конфигу Neovim хранится **не здесь**, а в Obsidian-vault:

```
~/Документы/obsidian/
```

Создавать `*.md`-файлы с документацией в `~/.config/nvim/` **нельзя** (исключение: README внутри сторонних плагинов в `lua/plugins/`, если их требует сам плагин).

### Куда класть

| Тема | Файл |
|---|---|
| Хоткеи (leader, general, LSP, DAP, git, терминал) | `obsidian/nvim/keymaps.md` |
| F-клавиши и C-F серия, терминальные коды (F25–F36) | `obsidian/nvim/fkeys.md` |
| Отдельные команды и утилиты (например `:TyCheck`) | `obsidian/nvim/<имя>.md` — один файл на тему |
| Описание плагинов, сколько и что делает | `obsidian/nvim/plugins.md` |
| Помощь по конкретному плагину | `obsidian/nvim/help/<плагин>.md` |
| Внешние инструменты (kaskade, docker, ssh и т.п.) | тематические папки vault: `obsidian/Брокеры сообщений/`, `obsidian/Хранилища и сервисы/`, `obsidian/Python/`, `obsidian/docker.md`, `obsidian/ssh.md` |

### Правила ведения

- Обновлять существующий файл вместо создания нового, если тема уже покрыта.
- В шапке файла указывать дату актуальности («Актуально на ГГГГ-ММ-ГГ») и источник (`keymaps.lua` и т.п.).
- Факты брать из фактического состояния конфига (проверять `nvim --headless`, grep по lua), не из памяти.
- Скрипты вне конфига (`~/bin/*`) документировать в тематических папках vault, не в `nvim/`.
- Обновлять документацию если в конфигурации появляется или исчезает команда или хоткей

## Код

- Патчи сторонних пакетов (например, kaskade в `~/.local/share/uv/tools/`) сопровождать комментарием в месте патча и упоминанием в соответствующем `.md` vault — патчи затираются при обновлении пакета.
- Экспериментальные файлы и дымовые тесты не оставлять: удалять после проверки.
